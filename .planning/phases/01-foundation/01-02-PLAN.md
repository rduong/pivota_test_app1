**2. Storage namespace — error-resilient localStorage wrappers:**
```javascript
const Storage = {
  get(key, fallback = null) {
    try {
      const raw = localStorage.getItem(key);
      return raw === null ? fallback : JSON.parse(raw);
    } catch (e) {
      console.warn(`[Storage] parse failed for key "${key}"`, e);
      return fallback;
    }
  },
  set(key, value) {
    try {
      localStorage.setItem(key, JSON.stringify(value));
    } catch (e) {
      console.warn(`[Storage] write failed for key "${key}"`, e);
    }
  },
  remove(key) {
    localStorage.removeItem(key);
  }
};
```

IMPORTANT: The `set` method MUST have a try/catch to handle `QuotaExceededError` (localStorage 5MB limit). Do NOT use direct `localStorage.setItem()` calls anywhere outside this wrapper.

**3. hashPassword — async SHA-256 via SubtleCrypto:**
```javascript
async function hashPassword(password) {
  const msgUint8 = new TextEncoder().encode(password);
  const hashBuffer = await window.crypto.subtle.digest('SHA-256', msgUint8);
  // Use Array fallback — Uint8Array.toHex() not available in Safari 14
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}
```

CRITICAL: This function is `async` — it MUST be called with `await`. If called without `await`, it returns a Promise object, NOT a hex string. Any code that calls `hashPassword()` MUST be in an `async` function.

**4. generateUUID — crypto.randomUUID() with Safari 14 polyfill:**
```javascript
function generateUUID() {
  if (typeof crypto.randomUUID === 'function') {
    return crypto.randomUUID();
  }
  // Polyfill for Safari 14 (randomUUID available in Safari 15.4+)
  return ([1e7]+-1e3+-4e3+-8e3+-1e11).replace(/[018]/g, c =>
    (c ^ crypto.getRandomValues(new Uint8Array(1))[0] & 15 >> c / 4).toString(16)
  );
}
```

Note: `crypto.randomUUID()` is NOT used in Phase 1 (no IDs needed for admin seed), but the foundation must be in place for Phases 2-4 which need UUID generation.

  <name>Task 2: Implement Bootstrap namespace (idempotent admin seed)</name>

  <action>
Add the Bootstrap namespace after Config, Storage, hashPassword, and generateUUID in the `<script>` block.

**Bootstrap namespace — idempotent first-run admin account seeding:**
```javascript
const Bootstrap = {
  async init() {
    // FR-F8.1: Check if users already exist — if so, do nothing (idempotency)
    const users = Storage.get(Config.KEYS.USERS, []);
    if (users.length > 0) {
      return { firstRun: false };
    }

    // FR-F8.2: First run — seed default admin account
    // MUST await hashPassword — it's async (SubtleCrypto returns Promise)
    const passwordHash = await hashPassword(Config.DEFAULTS.ADMIN_PASSWORD);
    const adminUser = {
      username: Config.DEFAULTS.ADMIN_USERNAME,
      passwordHash,            // 64-char hex SHA-256 string
      role: 'admin',
      registeredAt: new Date().toISOString(),
      inviteCode: null
    };
    Storage.set(Config.KEYS.USERS, [adminUser]);

    // FR-F8.3: Signal first-run state so Router can show first-run notice
    return { firstRun: true };
  }
};
```

**Key implementation rules:**
- `await hashPassword()` is MANDATORY — without it, `passwordHash` is a Promise object `[object Promise]`, login will NEVER succeed
- Check `users.length > 0` FIRST before doing anything — this is the idempotency guard (FR-F8.4)
- Return value `{ firstRun: boolean }` is passed to `Router.start()` in Plan 03 — the shape must match exactly
- Admin user object shape is EXACT per TechArch: `{ username, passwordHash, role, registeredAt, inviteCode }` — no extra fields, no renaming (`passwordHash` not `hashedPassword`, not `hash`)

**Do NOT add the DOMContentLoaded entry point here** — that will be added in Plan 03 once the Router is in place.
